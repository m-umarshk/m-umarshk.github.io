# Journey with C# Programming


When I first encountered C# in my second semester, my immediate reaction was confusion. Coming from a background in Python, which I had spent an entire semester learning and getting comfortable with, C# felt like stepping into a completely different world. The syntax was unfamiliar, the structure looked more complex, and for the first few weeks I genuinely struggled to find my footing in this new language.

The most challenging part at the beginning was the syntax. Python had always felt clean and readable — you could almost read it like plain English. C# was different. Curly braces, semicolons at the end of every statement, strict type declarations, and a much more structured format made every line of code feel like a puzzle. I would sit down to write something simple and spend more time figuring out the correct syntax than actually thinking about the logic of the program. It was frustrating, but looking back, that frustration was a sign that I was genuinely engaging with something new.

However, there was something reassuring underneath all the confusion — the concepts were familiar. Thanks to the foundation I had built in Python during my first semester, I already understood what variables, loops, conditions, and functions were supposed to do. Object Oriented Programming concepts like classes, objects, and methods were also not entirely new to me. The knowledge I had gained from my first semester meant that I was not learning everything from scratch. I was learning a new way to express ideas I already understood, and that made a significant difference in how quickly I was able to adapt.

Our course was taught by Dr. Akram, whose teaching approach helped us navigate through the complexities of C# step by step. He made sure we understood not just how to write C# code but why it is structured the way it is. Understanding the reasoning behind the syntax — why C# requires type declarations, why it uses object-oriented principles so strictly, and how it differs from interpreted languages like Python — helped me appreciate the language rather than just struggle with it. Gradually, the syntax that had once felt like a barrier started to feel more natural.

The real test came during the mid-semester examination, and I will be honest — it did not go well. I had underestimated how much the syntax differences between Python and C# would affect my performance under exam conditions. Writing code on paper or in an exam setting without the help of an IDE to catch errors exposed every gap in my understanding. That mid exam was a wake-up call. It reminded me of the lesson I had carried from my first semester — never take anything carelessly. I had not been as consistent in my practice as I should have been, and the result reflected that.

After the mid exam, I made a deliberate decision to change my approach. I started practicing more regularly, writing small programs every day to build muscle memory for the syntax, and revisiting concepts I had not fully understood. Slowly but steadily, things began to click. The confusion that had defined my early weeks with C# started to lift, and I began to feel more confident writing code and solving problems in the language. The concepts that had always made sense started to align with the syntax, and C# began to feel less like a foreign language and more like another tool I could use.

Towards the end of the semester, we were given a project — to build a game using C#. This was the moment where everything came together. Applying the concepts of Object Oriented Programming to a real, creative project made the learning feel purposeful and exciting. Building something that actually worked, that had logic and interaction and a visible outcome, was one of the most satisfying experiences of my second semester. It showed me that all the effort I had put in after the mid exam had paid off.

Looking back, my journey with C# was not smooth, but it was one of the most valuable learning experiences of my second semester. It taught me how to adapt, how to recover from a setback, and how to push through confusion until things start to make sense. The foundation I had built with Python made the journey easier, and the challenges I faced made me a stronger programmer. Every language has its own personality, and learning C# taught me that growth as a developer comes from being willing to start over, feel confused, and keep going anyway.
